## 2. 제품 의도

초대된 회의 참가자가 회의 전에 제출한 자료와 의견을 한곳에 모으고, **참가자가 실제로 말한 것**과 **LLM이 외부에서 조사한 것**을 혼합하지 않은 채 빠르게 읽을 수 있게 한다. 모든 생성 문장은 사용자가 원본 위치나 웹 출처까지 역추적할 수 있어야 한다.

## 3. 핵심 용어

- **원본(Original)**: 참가자가 직접 입력한 의견 또는 업로드한 파일의 보존본.
- **추출본(Extracted Source)**: 원본을 자체 파서/OCR로 읽어 구조화한 텍스트·레이아웃·좌표 데이터.
- **생성 스냅샷(Generation Snapshot)**: 주최자가 제출을 마감한 순간 포함된 원본 리비전의 불변 목록.
- **요약본(Summary)**: 생성 스냅샷의 참가자 원본만 충실히 압축한 문서. 웹 지식, 팩트체크 결론, LLM의 제안은 들어갈 수 없다.
- **LLM 조사본(Research Report)**: 주제 웹 조사와 참가자 주장 팩트체크를 담는 별도 문서.
- **RAG 태그/인용(Citation)**: 생성 문장과 근거 위치를 잇는 구조화된 링크. 텍스트 줄, PDF 페이지·문단, 이미지 영역, 표의 시트·셀, 향후 채팅 메시지 ID처럼 형식별 원본 좌표를 사용한다.
- **검증 가능 주장(Check-worthy Claim)**: 외부 독립 자료로 참·거짓·불확실 여부를 조사할 수 있는 참가자 발언. 의견과 가치판단은 제외한다.

## 4. 사용자와 권한

### 역할

- **사용자**: 친구 요청을 보내고 수락할 수 있다.
- **방 주최자**: 수락된 친구를 초대해 방을 만들고, 토크 세션의 주제·마감 시각을 정하며 제출을 마감하고 결과 생성을 시작한다.
- **초대된 참가자**: 방에 참가해 자료·의견을 제출하고 다른 참가자의 원본과 생성 결과를 본다.

### 권한 원칙

- 방 구성원만 방, 원본, 추출 미리보기, 요약본, 조사본을 열람할 수 있다.
- 주최자만 제출 마감과 1회 생성 작업을 시작한다.
- 마감 전에는 참가자가 자신의 제출을 수정/교체할 수 있다. 생성 스냅샷은 정확한 리비전을 고정한다.
- 마감 후 원본과 결과는 데모 범위에서 읽기 전용이다.

## 5. 첫 마일스톤 범위

### 5.1 포함

1. 기본 사용자 식별/로그인과 친구 요청·수락.
2. 수락된 친구를 초대하는 비공개 방 생성.
3. 전달형 토크 세션 생성: 제목, 회의 주제, 설명, 제출 마감 시각.
4. 참가자의 텍스트 의견 및 파일 제출.
5. 최소 보장 입력: PDF(텍스트 및 스캔), HWP, PNG, JPG/JPEG. 추가 형식은 파서 어댑터로 확장 가능하게 설계하되 첫 마일스톤 승인 조건은 아니다.
6. 원본 파일 보존, 방 구성원 대상 원본 목록/미리보기/다운로드.
7. 자체 파싱·OCR과 형식별 출처 좌표 생성.
8. 주최자 마감, 불변 생성 스냅샷, 1회 비동기 생성 작업.
9. 원본만 근거로 하는 요약본과 출처 인용.
10. 별도의 LLM 조사본:
    - 회의 주제 웹 조사 + 웹 URL 인용
    - 자동 선별한 참가자 주장 팩트체크 + 참가자 원문 인용 + 웹 URL 인용
11. Grok 최초 구현과 교체 가능한 LLM/웹조사 어댑터.
12. 대화형 후속 구현을 위한 공통 `Room`, `Session`, `Participant`, `Source`, `SourceAnchor`, `Citation`, `GenerationSnapshot`, `GeneratedDocument` 모델과 메시지/대화 세션 API 계약 초안.

### 5.2 명시적 비목표

- 음성·영상 업로드, STT, 화상회의
- 생성 문서의 실시간 공동편집·승인 워크플로
- 비회원 공개 링크, PDF/DOCX 내보내기
- iOS/Android 네이티브 앱
- 결제, 과금, 조직 관리자 분석
- 대화형 모드의 완성된 채팅 UI·실시간 전송·종료 후 생성 플로우
- 상용 수준의 규정 준수 인증, 다중 리전, 고가용성, 정교한 운영 모니터링

## 6. 핵심 사용자 흐름

1. 사용자가 로그인하고 친구 요청을 주고받는다.
2. 주최자가 수락된 친구를 초대해 비공개 방을 만든다.
3. 주최자가 전달형 토크 세션과 회의 주제·마감을 생성한다.
4. 참가자가 텍스트 의견 또는 파일을 제출한다.
5. 시스템은 원본을 서비스 저장소에 보존하고 자체 파싱/OCR로 추출본과 출처 좌표를 만든다.
6. 방 구성원은 모든 참가자의 원본과 처리 상태를 본다.
7. 주최자가 제출을 마감한다. 이후 제출은 잠기고 정확한 원본 리비전 목록이 스냅샷으로 고정된다.
8. 시스템이 비동기 작업으로 요약본과 조사본을 생성한다.
9. 사용자가 요약 문장의 인용을 누르면 원본 미리보기의 해당 줄·페이지·문단·이미지 영역으로 이동한다.
10. 조사본의 주제 조사 문장을 누르면 웹 출처를 확인한다.
11. 팩트체크 항목에서 대상 참가자 주장과 웹 근거를 각각 확인한다.

## 7. 출력 계약

### 7.1 요약본

- 입력은 생성 스냅샷의 추출본으로 제한한다.
- 참가자의 관점, 합의, 이견, 핵심 근거를 충실히 압축한다.
- 웹 검색 결과, LLM 상식 보충, 팩트체크 판정, 행동 제안은 금지한다.
- 요약의 근거 문장/항목에는 하나 이상의 원본 인용이 있어야 한다.
- 근거가 없는 내용을 새 사실처럼 생성하면 실패로 취급한다.

### 7.2 LLM 조사본

두 섹션을 명확히 분리한다.

1. **주제 자료조사**
   - 회의 주제에서 핵심 조사 질문을 도출한다.
   - Grok 웹 검색을 사용한다.
   - 외부 사실과 분석 문장에 URL 인용을 붙인다.
   - 조사 시각과 출처 제목/도메인을 보존한다.

2. **참가자 주장 팩트체크**
   - 검증 가능한 핵심 주장만 자동 선별한다.
   - 각 항목은 `대상 주장`, `원본 RAG 태그`, `판정`, `설명`, `웹 근거 RAG 태그`를 가진다.
   - 판정은 최소 `근거가 지지함`, `근거가 반박함`, `근거가 엇갈림`, `확인 불가`를 구분한다.
   - 의견·예측·가치판단을 사실 오류로 표시하지 않는다.
   - 상충하거나 불충분한 근거를 강제 이진 판정하지 않는다.

## 8. 출처·RAG 데이터 계약

### 핵심 엔터티

- `SourceArtifact`: 원본 제출 단위, 소유 참가자, 파일 메타데이터, 저장 키, 해시, 처리 상태.
- `SourceRevision`: 마감 스냅샷에 고정되는 제출 리비전.
- `ExtractedBlock`: 파싱된 텍스트/레이아웃 블록과 OCR 신뢰도.
- `SourceAnchor`: 형식별 위치 식별자.
- `Citation`: 생성 문서 범위와 하나 이상의 원본/웹 근거를 연결.
- `GenerationSnapshot`: 마감 시점의 포함 리비전과 주제/참가자 목록.
- `GeneratedDocument`: `summary` 또는 `research` 유형, 생성 상태, 모델/프롬프트 버전, 스냅샷 ID.
- `ResearchClaim`: 팩트체크 대상 주장, 원본 인용, 판정, 웹 근거 인용.

### 권장 `SourceAnchor` 변형

- `text_line`: 시작/끝 줄 + 문자 오프셋
- `pdf_block`: 페이지 + 블록/문단 ID + 선택 영역
- `image_bbox`: 이미지 ID + 정규화된 bounding box + OCR 텍스트
- `sheet_cell`: 시트 + 셀/범위
- `chat_message`: 향후 대화형용 메시지 ID + 작성자 + 시각
- `web_url`: URL + 제목 + 접근 시각 + 인용 텍스트 해시/스니펫

### 불변성

- 인용은 파일명이 아니라 `SourceRevision`과 `SourceAnchor`를 참조한다.
- 생성 후 원본 표시 이름이 바뀌어도 인용 대상은 바뀌지 않는다.
- 원본 미리보기에서 위치를 찾지 못하는 인용은 깨진 인용으로 검증 실패 처리한다.

## 9. LLM·검색 경계

- 최초 공급자는 Grok이다. 현재 공식 문서상 Grok 4.5는 웹 검색과 URL/인라인 인용을 지원한다: [Web Search](https://docs.x.ai/developers/tools/web-search), [Citations](https://docs.x.ai/developers/tools/citations), [Grok 4.5](https://docs.x.ai/developers/grok-4-5).
- 요약과 조사는 서로 다른 유스케이스/프롬프트/출력 스키마를 사용한다.
- 공급자별 응답을 내부 `SummaryResult`, `ResearchResult`, `CitationEvidence` 스키마로 정규화한다.
- 원본 파일 자체를 xAI Files API에 업로드하지 않는다. 서비스가 추출한 필요한 텍스트/이미지 조각만 전송한다.
- API 키, 유료 호출, 실제 외부 배포는 사용자 승인 없이는 수행하지 않는다. 키가 없을 때는 결정론적 목(mock)/fixture로 전체 흐름을 시연할 수 있어야 한다.

## 10. 실패·경계 사례

- 지원되지 않거나 손상된 파일: 원본은 보존하되 `처리 실패`와 이유를 표시하고 생성 스냅샷 포함 여부를 주최자가 알 수 있게 한다.
- 낮은 OCR 신뢰도: 해당 블록에 경고를 표시하고 요약 인용에서 신뢰도를 노출한다.
- 마감 직전 수정: 마감 트랜잭션이 고정한 리비전만 생성에 사용한다.
- 생성 중 오류: 스냅샷은 유지하고 같은 스냅샷에 대해 재시도할 수 있으나 성공 결과는 한 버전만 활성화한다.
- 웹 근거 없음/상충: `확인 불가` 또는 `근거가 엇갈림`으로 표시한다.
- 웹 링크 변경/삭제: URL, 제목, 접근 시각, 인용 스니펫 해시를 남겨 당시 근거를 식별한다. 전체 웹페이지 복제는 하지 않는다.
- 요약에 외부 정보 혼입: 출력 검증/평가에서 치명적 실패로 처리한다.

## 11. 테스트 가능한 승인 기준

### 사용자·방

- [ ] 친구 요청을 수락한 사용자만 방 초대 후보가 된다.
- [ ] 비구성원은 방의 원본·추출본·생성 문서를 읽을 수 없다.
- [ ] 주최자만 제출을 마감하고 생성을 시작할 수 있다.

### 제출·원본

- [ ] 텍스트 의견, PDF, HWP, PNG, JPG/JPEG 샘플을 제출하고 원본을 다시 열 수 있다.
- [ ] 스캔 PDF/이미지에서 OCR 추출 결과와 원본 영역 좌표가 생성된다.
- [ ] 처리 실패 파일도 삭제되지 않고 사용자에게 실패 상태가 보인다.
- [ ] 마감 후 생성 스냅샷의 파일 해시·리비전 목록이 변하지 않는다.

### 요약본

- [ ] 요약본의 근거 항목은 모두 하나 이상의 원본 인용을 가진다.
- [ ] 모든 원본 인용 링크가 올바른 제출자·파일·형식별 위치로 이동한다.
- [ ] 외부 웹 조사 문장이나 팩트체크 판정이 요약본에 나타나지 않는다.
- [ ] 근거 없는 요약 문장을 탐지하는 평가 fixture가 실패를 재현한다.

### 조사본

- [ ] 주제 조사 문장마다 사용한 웹 URL 인용을 확인할 수 있다.
- [ ] 각 팩트체크 항목은 대상 참가자 주장 인용과 웹 근거 인용을 모두 가진다.
- [ ] 의견·가치판단은 팩트체크 대상에서 제외된다.
- [ ] 지지/반박/상충/불충분 fixture가 각각 올바른 상태로 표현된다.
- [ ] 조사 결과는 요약본 저장 객체를 수정하지 않는다.

### 개인정보·공급자

- [ ] Grok 어댑터 요청에는 원본 저장 URL/원본 파일 바이트가 포함되지 않고 필요한 추출 조각만 포함된다.
- [ ] 공급자 어댑터를 목 구현으로 교체해도 핵심 사용자 흐름과 인용 렌더링이 동작한다.
- [ ] API 키 없이 로컬 데모 fixture로 전체 흐름을 재현할 수 있다.

### 대화형 기반

- [ ] 공통 출처/인용 모델이 향후 `chat_message` 원본을 수용할 수 있다.

## 12. 구현자 결정 경계

### 별도 확인 없이 결정 가능

- 프론트엔드/백엔드 프레임워크, 언어, 패키지 구조
- 로컬 DB·객체 저장소·작업 큐의 구체적 선택
- 위 계약을 지키는 API 경로·테이블·컴포넌트 명칭
- 테스트 도구, 목/fixture 구성, 로컬 컨테이너 구성
- 형식별 파서/OCR 라이브러리 선택(새 유료 서비스는 제외)

### 반드시 별도 승인 필요

- 실제 클라우드/외부 운영 배포
- 유료 API/인프라 사용 또는 사용자의 자격증명 입력·저장
- 원본 파일을 제3자에게 직접 업로드하는 변경
- 비목표 기능을 첫 마일스톤에 추가하는 범위 확대
- 요약본에 웹 조사/팩트체크 내용을 섞는 출력 계약 변경

## 13. 가정과 해결 상태

- **해결됨**: 전달형은 회의 전 준비용이며 주최자 마감 후 1회 생성한다.
- **해결됨**: “줄 인용”은 모든 형식을 억지로 줄로 바꾸는 것이 아니라 형식별 원본 위치 인용이다.
- **해결됨**: Grok은 기본 공급자지만 교체 가능해야 한다.
- **해결됨**: 외부 전송은 필요한 추출 조각으로 제한한다.
- **계획 단계 세부화 가능**: 정확한 기술 스택, 파일 크기/개수 제한, OCR 라이브러리, 비동기 작업 큐, 로컬 데모 계정 방식.
- **잔여 위험**: HWP·스캔 품질, 웹 출처 신뢰도, LLM 인용 누락은 구현 및 평가 설계에서 별도 완화가 필요하다.
