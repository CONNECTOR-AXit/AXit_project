## 1. 배경

이전 승인(`docs/provider-experiment-live-xai-amendment.md`)은 **합성 데이터로 된
1회성 smoke 호출**만 허용했다. 이번 요청은 성격이 다르다 — "새 프로젝트 만들기"
화면에서 사용자가 입력한 프로젝트 설명을 다듬어주는 **"설명 구체화" 버튼**을
만들고, 클릭 시 xAI Grok API를 호출해 몇 가지 구체화된 설명 선택지를 사용자에게
제시한다. 이는 반복적으로, 실제 서비스 사용자를 대상으로, 실제(합성이 아닌)
사용자 입력을 가지고 호출된다는 점에서 이전 승인 범위를 명확히 벗어난다.
프로젝트 소유자가 이 확장된 사용을 본 세션에서 직접 승인했다.

## 2. 허용 범위

1. 새 프로젝트 생성 다이얼로그의 "설명 구체화" 버튼 클릭 시에 한해,
   사용자가 입력한 **프로젝트명 + 설명 초안**(회의/문서 원본이 아님)을
   xAI Responses API로 전송할 수 있다.
2. 요청마다 `store: false`를 유지하고, 도구(web/X search, code execution,
   파일 업로드)는 사용하지 않는다.
3. 응답은 구조화된 JSON(설명 선택지 2~4개)만 받으며, 자유 형식 채팅이나
   멀티턴 대화는 만들지 않는다.
4. 실패·타임아웃 시 자동 재시도하지 않고, 사용자에게 "지금은 제안을
   가져올 수 없습니다" 같은 안전한 오류만 보여준다.
5. API 키는 배포 환경변수(`XAI_API_KEY`)로만 공급하며, 저장소에 커밋하거나
   로그에 남기지 않는다.

## 3. 계속 금지되는 사항 (변경 없음)

- 업로드된 원본 문서·회의 내용을 이 기능에 사용하는 것 (오직 사용자가
  프로젝트 생성 화면에서 직접 타이핑한 제목/설명 텍스트만 전송한다.)
- API 키를 Git 추적 파일, `.env.example`, 로그, DB에 기록
- 브라우저/프런트엔드에 API 키를 직접 전달 (호출은 항상 백엔드에서만 수행)
- web search, X search, code execution, 파일 업로드 tool 사용
- 응답을 그대로 자동 저장·확정하는 것 — 사용자가 선택지 중 하나를 직접
  고르거나 무시할 수 있어야 한다.
- 이 승인 범위를 벗어난 다른 기능에 xAI를 쓰는 것. 단, 2026-08-10 승인된
  `provider-experiment-full-report-pipeline-amendment.md`의 현재 사용자 보고서
  파이프라인은 별도 승인 범위이며 이 금지와 충돌하지 않는다.

## 4. Credential 계약

`XAI_API_KEY`는 배포 환경의 secret 또는 `.env`(gitignored)로만 공급한다.
`.env.example`에는 빈 자리표시자만 둔다.

## 5. 활성화 기록

**활성화 기록 (2026-08-08):** 프로젝트 소유자가 본 채팅 세션에서 (1) 설명이
Grok에 전달되는지 질문 → (2) 현재는 전달되지 않으며 AGENTS.md가 이런 반복
프로덕션 호출을 금지한다는 설명을 들은 뒤 → (3) "사용자가 명시적으로
승인하므로 실제 grok API로 연결"을 직접 선택했다. 범위는 본 문서 §2에 정의된
설명 구체화 기능으로 한정되며, 다른 프로덕션 xAI 통합을 승인하지 않는다.
